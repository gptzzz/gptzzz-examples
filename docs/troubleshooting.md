# 按错误发生的位置排查 GPTZZZ 请求

此项目面向 [gptzzz.ai](https://gptzzz.ai/)，站方品牌名为 KaiGPT。下面是配套代码的排错方法，协议参考[站方接入教程](https://gptzzz.ai/blog/openai-api-quickstart/)与[错误码手册](https://gptzzz.ai/docs/api-error-codes/)。示例验证范围为**本地模拟响应；真实账号可用性未测试**。本地能处理模拟错误，不代表线上会返回完全相同的字段。

**先保存一次失败的证据**

在项目根目录复现最短请求：

```sh
python3 scripts/chat.py --prompt '用一句话解释 API 中转站'
```

先看是否拿到 HTTP 状态。没有状态时，优先区分 DNS、连接、TLS 与读响应阶段；有状态时，结合响应头和正文中的 `error.type`、`error.code` 判断。字段也可能缺失，代理可能返回 HTML，不能强行把所有失败解析成同一类 JSON 错误。

当前 CLI 只给出文字结果或简要错误，不输出服务端原始错误正文，也不采集结束原因、耗时和请求 ID。若需要 `error.type`、`error.code` 等详细字段，请查看账户调用记录或另行扩展脱敏采集。记录时间、最终 URL、模型、状态及已获得的证据；未采集的字段标“未采集”，不要推断服务端没有返回。不要为了排错打印完整密钥或完整业务提示词。

| 现象 | 优先检查 | 下一步 |
|---|---|---|
| **400** | JSON 是否有效；`model`、`messages` 的类型和结构；参数支持范围、上下文长度 | 恢复最小正文，每次只改一项；修正前不重试 |
| **401** | 环境变量是否进入当前进程，Bearer 格式、密钥所属平台及状态 | 修复鉴权；轮换失效密钥时同步更新配置 |
| **403** | 当前账号、项目、密钥或模型的权限与策略 | 阅读具体错误，核对控制台；不要反复更换参数碰运气 |
| **404** | 请求主机和资源路径，是否重复或遗漏 `/v1`；然后查模型 ID 与权限 | 先定位路径，再排模型；不能一概归为“模型不存在” |
| **429** | 错误指向速率、并发限制，还是额度、余额或其他配额 | 仅确认暂时限流时考虑退避；额度问题先核对账号状态 |
| **5xx** | 错误可能由中转网关或上游产生；检查请求 ID、发生时间和是否持续 | 保留证据；只有确认适合重试的情况才限次处理 |
| **超时** | 连接阶段还是发送后的等待阶段；是否收过响应头或部分正文 | 结果可能未知，先查请求记录，避免立即重复提交 |

**把路径与模型分开验证**

`GPTZZZ_BASE_URL` 应为 `https://gptzzz.ai/v1`，聊天资源是 `/chat/completions`。即使 Base URL 正确，也不能推断 `/responses` 等其他端点可用。确认路径后，从当前账号复制模型 ID；营销名称、旧截图和其他平台的模型名都不能替代它。

`python3 scripts/list_models.py` 对应的 `/v1/models` 仅有站方文档建议，本项目未做真实账号测试。它返回 404 时，应核查该资源是否开放，不能据此断定 Key 或所有模型失效。

**重试必须有停止条件**

先修复 400、401、403、404 的明确原因。429 若属于额度不足，等待不会自动恢复额度；若属于暂时限流，可参考 `Retry-After`，设置最大尝试次数与总等待时间，采用带随机抖动的退避，并避免在多层客户端重复重试。

5xx 或读超时并不证明服务端没有执行。请求可能已完成或已计费，重发可能重复产生结果和费用；先保留请求 ID 并核对账户记录。不要推定此服务支持 `Idempotency-Key`，也不要认为添加该头就能去重。本文不建议自动无限重试。

问题消失后，重新执行同一条最小请求，核对正文与结束原因，再恢复较长输入。反馈给站方时提供脱敏诊断信息，不发送密钥；一个成功样例只证明该次请求成立，不应扩展成所有模型与能力都已验证。
